## 1. 背景与问题

### 1.1 现状

面对大量记忆性学习任务的用户（考研、考证、语言学习、医学/法条等专业记忆），当前主流方案是 Anki 一类的记忆卡片工具。这类工具的核心缺陷是**制卡成本高、卡片来源受限、学习计划需要用户自己维护**：

- **制卡重**：从 PDF、网页、课件里提炼知识点并拆成问答对，是纯粹的重复劳动，用户往往在制卡阶段就放弃。
- **来源窄**：特定领域（如某本教材、某份讲义）没有现成卡片库，用户只能手工录入。
- **计划负担**：复习节奏、每日任务量、优先级全部由用户自己判断，缺乏一个「替我做决定」的角色。
- **答疑割裂**：用户遇到不懂的卡片，需要跳出应用去搜索，学习上下文断裂。

### 1.2 机会

大模型具备**信息抽取、结构化生成、规划与答疑**能力，恰好覆盖上述四个缺陷。把 Agent 放进卡片产品的核心链路，可以让「资料 → 卡片 → 计划 → 复习 → 答疑」形成闭环。

### 1.3 更远的判断

卡片不应只承载知识点。它可以是日程、回忆、灵感。如果从第一天起就把「卡片类型」做成可插拔的能力包（显示格式 / 运行形式 / 生成工作流 / 知识库建立方式），产品就能从「记忆卡片工具」长成「通用卡片助手」。**这是本项目与 Anki 类产品的根本分野，也是 MVP 架构必须提前付出的成本。**

## 2. 产品定位

### 2.1 一句话定位

> **CardSharp 是一个可拓展的 AI 卡片助手：用 Agent 把用户的资料变成可运行的卡片集合，并用长期学习计划驱动用户持续记忆。**

### 2.2 核心价值主张

| # | 价值 | 对应痛点 |
| --- | --- | --- |
| V1 | **零成本制卡**：导入资料，Agent 生成可复习的卡片集，用户只做确认与微调 | 制卡重 |
| V2 | **Agent 排程**：不需要用户自己决定今天学什么，Agent 结合记忆曲线与卡片质量给出计划，用户一键同意 | 计划负担 |
| V3 | **卡片即知识库**：卡片集同时是可检索的知识库，答疑助手基于「你自己的卡片」回答，而不是通用模型泛泛而谈 | 答疑割裂 |

### 2.3 目标用户（MVP 聚焦）

**主画像：备考型学习者**

- 年龄 18–30，学生或职场转行者
- 手上有明确的学习资料（PDF 教材、课件、网课笔记、网页文章）
- 每天可投入 20–60 分钟碎片时间，主要在手机上
- 有明确的考试/认证截止日期
- 用过或听说过 Anki，但被制卡成本劝退

**次画像（MVP 覆盖但不重点优化）**

- 需要记录灵感的写作者
- 长期写日记/随笔的人

### 2.4 非目标（MVP 明确不做）

- ❌ 不做卡片社区、发布、打卡、卡片仓库
- ❌ 不做 AI 配图生成
- ❌ 不做桌面端 / Web 制卡台（**MVP 仅移动端**，制卡入口在手机：拍照 / 相册 / 文件 / 链接）
- ❌ 不做多人协作 / 共享卡片集
- ❌ 不做复杂层级文件夹（MVP 只做单层）
- ❌ 不做插件市场 / 用户自定义 Agent

> **关于「电脑制卡、同步到移动端」**：该设想在 MVP 阶段**明确放弃**。
>
> 理由：移动端已能完成「拍照 / 文件导入 → 草稿确认 → 落库」全链路；引入第二端会带来账号同步、UI 双份维护、测试矩阵翻倍的固定成本，而这些成本换不来核心价值验证。
>
> Flutter 选型保证未来补桌面端**不需要重写业务逻辑**，但该能力**不排入任何 MVP 里程碑**，也不作为 P1 承诺。

> **关于「卡片社区」**：设计稿底部导航保留了「社区」入口，但 MVP 阶段该 Tab **置灰并提示「即将上线」**，不实现任何功能。保留入口是为了验证导航结构，避免后续改版。

## 3. 核心场景（Jobs To Be Done）

### JTBD-1 把资料变成卡片

> 当我手上有一份 60 页的 PDF 讲义，我想把它变成能复习的卡片，这样我不用逐页手抄。

**关键约束**：我不能接受 Agent 直接写入几百张烂卡片。我需要**先看草稿、再决定**。

### JTBD-2 每天知道该学什么

> 当我打开 App，我想知道今天该复习哪些卡片，这样我不用自己算记忆曲线。

**关键约束**：计划必须是**可解释**的（为什么今天这些卡片），且**可调整**（今天没时间，能不能少一点）。

### JTBD-3 复习时自检

> 当我进入复习，我想看到卡片明文、自己回忆、翻页核对暗文、然后诚实评分。

**关键约束**：

- 必须**离线可用**，地铁上没信号也要能复习。
- 排程**不由我操心**——服务端 Agent 已经算好了今天该复习什么，我只是消费队列。
- 但我希望**能自己翻卡片**，不进入复习也能随便看看。

### JTBD-4 遇到不懂就问

> 当我对一张卡片的内容有疑问，我想**不离开当前页面**直接问助手，并且它的回答基于我自己的卡片集。

**关键约束**：回答要**引用来源卡片**，否则我无法判断可信度。答疑区应该内嵌在卡片页面里，而不是跳转到独立 Tab。

### JTBD-5 管理我的卡片

> 当我有十几个卡片集，我想分类、打标签、搜索、编辑，这样我找得到、改得动。

### JTBD-6 按我的节奏学

> 我是冲刺型考生 / 我记性很好，我不想要一套固定的复习节奏。

**关键约束**：排程策略必须能**按学习模式切换**（标准 / 冲刺 / 强记忆），并且切换后要**解释**为什么这样排。

## 4. 需求总览

| Epic | 名称 | 优先级 | 说明 |
| --- | --- | --- | --- |
| E1 | 账号与设备 | P0 | 注册登录、设备管理、推送令牌 |
| E2 | 卡片与集合管理 | P0 | 文件夹、卡片集、卡片 CRUD、标签、搜索 |
| E3 | 制卡流水线 | P0 | 资料导入 → Agent 生成 → 预览确认 → 落库 |
| E4 | 记忆训练 | P0 | **排程 Agent**、卡片页面（明文/暗文/图片/内联答疑）、离线队列、自由浏览 |
| E5 | 长期学习计划 | P0 | Agent 规划、计划确认、每日推送、进度追踪 |
| E6 | 知识库与答疑 | P0 | 卡片集向量化、RAG 检索、引用式回答、**卡片内联答疑区** |
| E7 | 通知与提醒 | P1 | 复习提醒、计划提醒、静默时段 |
| E8 | 通用卡片系统扩展点 | P0 | 卡片类型注册、集合配置、运行器接口 |

> P0 = MVP 必须交付；P1 = MVP 内可降级但应尽量交付；P2 = 后续版本。
>
> **排程归属**：排程逻辑属于 E4（服务端 Agent），**不属于客户端**。客户端只消费已排期队列。

### 4.1 信息架构

依据 [卡片页面设计稿](卡片页面.png)，MVP 采用**底部三 Tab + 侧栏**结构：

> **2026-11-24 人类确认**：以设计稿为准，取消原先并列的「卡片集」「卡片」两个 Tab，合并为一个「卡片」Tab——
> 入口即书架首页（卡片集封面网格），点卡片集进入卡片集详情页（封面 / 简介 / 卡片列表）。

| Tab | 页面 | 说明 |
| --- | --- | --- |
| **卡片** | 书架首页（卡片集网格） | 卡片集封面 + 名称；点进入卡片集详情 |
| **助手** | 全局答疑 | 独立对话，可指定卡片集范围 |
| **社区** | 占位 | MVP **置灰**，提示「即将上线」 |

**侧栏**（Tab 内左滑或点击左上角）：

- 搜索（全局 / 当前卡片集）
- 学习模式切换（标准 / 冲刺 / 强记忆）
- 设置、统计

**页面层级**：

```
卡片集列表
└── 卡片集详情（封面图片 + 卡片列表）
    ├── 卡片复习页 ── 明文 / 暗文 / 图片 / 内联答疑 / 小星星 / 翻页
    ├── 卡片管理页 ── 更多菜单 / 运行按钮
    └── 制卡入口   ── 导入资料 → 草稿确认
```

## 5. 详细功能需求

### E1 账号与设备

#### FR-1.1 注册与登录 `P0`

- 支持**邮箱 + 密码**与**手机号 + 验证码**两种方式。
- 登录态使用 JWT（Access Token 短期 + Refresh Token 长期），Refresh Token 可撤销。
- 支持「退出登录」与「退出所有设备」。

> **本期落地口径（2026-11-24 人类确认）**：客户端先以 `FakeAuthRepository`（内置测试账号
> `test` / `123456`，本地比对、不联网）打通登录页、登录态与路由守卫；**分层与接口形状仍按
> `docs/03` §7 的 `features/auth` 四层保留**。后端 `/auth/*` 就绪后，只替换 Repository 实现
> 与 Provider 注入点，页面与状态机不改。JWT 存取、Refresh 轮换等按本节要求实现，但不在本期交付。

**验收标准**

- Given 未注册邮箱，When 提交注册，Then 创建账号并自动登录，收到验证邮件。
- Given 已登录用户，When 在第二台设备登录，Then 两台设备同时有效，设备列表可见两条记录。
- Given 用户在设备 A 退出所有设备，When 设备 B 发起请求，Then 返回 401 并跳转登录页。

#### FR-1.2 设备与推送令牌 `P1`

- 记录设备型号、系统版本、推送令牌、最后活跃时间。
- 推送令牌变更时自动更新。

### E2 卡片与集合管理

#### FR-2.1 单层文件夹 `P0`

- 用户可创建、重命名、删除、排序文件夹。
- 文件夹**只有一层**，不支持嵌套。
- 删除文件夹时，其下卡片集移动到「未分类」，不级联删除。

**验收标准**

- Given 存在文件夹「考研政治」，When 用户删除该文件夹，Then 文件夹消失，原卡片集出现在「未分类」，卡片本身不受影响。

#### FR-2.2 卡片集（Deck）`P0`

- 卡片集是卡片的容器，绑定**一个卡片类型**（MVP 固定为 `memory`）。
- 卡片集包含：标题、描述、封面色、所属文件夹、类型配置（JSON）、统计信息（总卡片数、今日待复习数）。
- 支持创建、重命名、删除、移动到文件夹。

**验收标准**

- Given 用户创建卡片集时未指定类型，Then 默认 `memory`。
- Given 卡片集被删除，When 用户确认删除，Then 卡片集与其下所有卡片进入回收站，30 天后物理删除。

#### FR-2.3 卡片 CRUD `P0`

- 卡片字段（`memory` 类型）：明文、暗文、可选图片、可选标签、备注。
- 支持手动新建、编辑、删除、批量移动、批量打标签。
- 编辑卡片内容时，**不重置**其复习进度（stability / difficulty 保留），但记录一次内容变更。

**验收标准**

- Given 一张已复习 10 次的卡片，When 用户修改暗文并保存，Then 卡片内容更新，`due_at` 与 `stability` 保持不变。

#### FR-2.4 标签与搜索 `P0`

- 用户可自定义标签，标签为全局维度（跨卡片集）。
- 搜索支持：全局搜索 / 指定卡片集内搜索。
- 搜索范围：卡片明文、暗文、标签、所属卡片集名称。
- 中文搜索使用 `pg_trgm` + `tsvector` 混合，支持模糊匹配。

**验收标准**

- Given 用户输入「唯物」，Then 返回明文或暗文包含该词的卡片，命中词高亮。
- Given 用户在卡片集内搜索，Then 结果限定在该卡片集。

#### FR-2.5 回收站 `P1`

- 删除的卡片/卡片集进入回收站，支持恢复与彻底删除。
- 30 天自动清理。

### E3 制卡流水线

> **这是 MVP 最核心、最复杂的链路。** 设计原则：Agent 产出**草稿**，用户**确认**后才落库。

#### FR-3.1 资料导入 `P0`

支持的资料类型：

| 类型 | 入口 | 处理方式 |
| --- | --- | --- |
| PDF | 文件选择器 | 文本层抽取；扫描件走 OCR（P1） |
| 网页链接 | 粘贴 URL | 正文抽取（Readability 算法） |
| 图片 | 拍照 / 相册 | 视觉模型 OCR + 理解 |
| 纯文本 | 直接粘贴 | 直接使用 |

- 单文件上限 50 MB，单次导入上限 5 个文件。
- 资料原件存入对象存储，与卡片集关联。
- 抽取失败时给出明确错误提示，允许重试。

**验收标准**

- Given 用户上传 30 页 PDF，When 解析完成，Then 显示页数与抽取字符数，可进入生成。
- Given 上传加密 PDF，Then 提示「文件受密码保护，无法解析」。
- Given 上传纯图片 PDF，Then 提示「未检测到文本层，将使用 OCR」（P1）。

#### FR-3.2 生成配置 `P0`

用户可配置：

- 生成数量（10 / 20 / 30 / 自定义，上限 100）
- 难度（基础 / 标准 / 进阶）
- 语言（跟随资料 / 中文 / 英文）
- 是否包含图片（MVP 固定关闭）
- 补充指令（自由文本，如「重点考查时间线」）

#### FR-3.3 生成过程 `P0`

- 生成任务异步执行，前端展示**流式进度**（阶段 + 百分比 + 已生成卡片数）。
- 阶段：`解析资料 → 抽取知识点 → 生成卡片 → 去重与质检 → 待确认`
- 支持取消任务。
- 单次生成超时 10 分钟，超时标记失败并保留已生成部分。

**验收标准**

- Given 生成任务进行中，When 用户退出页面再进入，Then 任务仍在后台运行且进度正确。
- Given 用户点击取消，Then 任务停止，已生成的卡片草稿保留在草稿箱。
- Given 生成失败，Then 展示失败原因与「重试」按钮，不消耗用户配额。

#### FR-3.4 草稿预览与确认 `P0`

- 以卡片列表形式展示草稿，支持**逐张编辑**（明文/暗文/标签）。
- 支持**逐张删除**、**全选/反选**。
- 显示质检结果：重复卡片（与已有卡片相似度高）标记为「疑似重复」，默认不勾选。
- 用户点击「导入到卡片集」后，选中的卡片才真正落库。
- 落库时初始化复习状态为「新卡」，`due_at = 现在`。

**验收标准**

- Given 生成 30 张草稿，When 用户取消勾选 5 张并确认，Then 卡片集新增 25 张卡片，草稿箱清空。
- Given 草稿与已有卡片相似度 > 0.9，Then 默认不勾选并标注「疑似重复」。
- Given 用户关闭 App 未确认，Then 草稿保留 7 天，可在「草稿箱」继续。

#### FR-3.5 生成质量要求 `P0`

- 卡片必须**自包含**：不依赖上下文即可理解（不使用「上文提到的」「该概念」等指代）。
- 每张卡片只考查**一个**知识点。
- 明文为问题/提示，暗文为答案，长度限制：明文 ≤ 200 字，暗文 ≤ 500 字。
- 禁止生成「是/否」型低价值卡片。

### E4 记忆训练

> **核心决策：排程由 Agent 负责，不是固定公式。**
>
> 不同用户的学习目标差异极大——「考试冲刺」需要短期高强度、按考纲优先级压缩间隔；「记忆力强」需要拉长间隔、减少无效重复。固定参数的 FSRS 无法同时满足，因此排程交给 Agent，由它结合**用户画像**与**卡片质量**做决策。
>
> 但 Agent 的输出**必须经过确定性护栏校验**（间隔单调性、上下界、每日预算），违反时降级为确定性兜底并告警。详见 [设计文档 · 排程 Agent](03-MVP设计文档.md#52-排程-agent)。

#### FR-4.1 复习会话 `P0`

- 入口：卡片集详情页「开始复习」/ 首页「今日任务」。
- 会话队列 = 服务端**已排期**的今日队列（`due_at <= now`），客户端只消费，不计算。
- 卡片页面（见 FR-4.5）展示明文 → 用户回忆 → 翻页揭示暗文 → 小星星评分。
- 支持手势：左滑 = 忘记，右滑 = 记住（可配置）。
- 会话结束展示统计：复习张数、正确率、耗时、下次复习时间。

**验收标准**

- Given 今日有 20 张到期卡片，When 用户开始复习，Then 队列为 20 张，顺序由服务端排程决定。
- Given 会话中途退出，Then 进度已保存，重新进入从断点继续。
- Given 用户对一张卡片评分「忘记」，Then 该卡片在本会话中会再次出现（间隔 ≥ 5 张）。

#### FR-4.2 排程 Agent `P0`

排程由**服务端 Agent** 在每次复习记录同步后批量执行，客户端不参与。

**用户画像（Learner Profile）** 驱动排程策略：

| 模式 | 适用 | 排程特征 |
| --- | --- | --- |
| `standard` 标准 | 常规备考 | 目标保留率 0.9，均衡间隔 |
| `sprint` 考试冲刺 | 考期临近（≤ 30 天） | 压缩间隔、提高每日新卡上限、按考纲优先级排序、允许「超量复习」 |
| `strong_memory` 强记忆 | 自评记忆力好 | 拉长间隔、降低复习频次、减少无效重复 |
| `custom` 自定义 | 高级用户 | 手动指定目标保留率与每日预算 |

**Agent 的确定性工具**（LLM 只能调用，不能自己算）：

- `compute_retrievability(stability, elapsed_days)` — 遗忘曲线
- `estimate_interval(stability, retention)` — 间隔估算
- `get_due_cards(deck_ids, horizon)` — 到期卡片
- `get_card_quality(card_ids)` — 错误次数、难度、历史评分
- `check_budget(plan, daily_minutes)` — 时间预算校验

**输出**：`SchedulePlan` —— 每张卡片的下次 `due_at` + 一句话理由（可解释性）。

**确定性护栏**（代码，非 LLM）：

- 间隔单调性：同一卡片，评分越高间隔越长
- 间隔上下界：`[1 天, 365 天]`
- 每日预算：预计耗时 ≤ 用户设定时长 × 1.15
- 幂等：同一 `review_id` 重复同步不重复排程

违反护栏时：降级为确定性 FSRS 计算，并记录 `scheduler.fallback` 告警。

**验收标准**

- Given 用户选择「考试冲刺」模式，When 生成排程，Then 平均间隔显著短于「标准」模式。
- Given 用户选择「强记忆」模式，Then 同一张卡片的间隔长于「标准」模式。
- Given Agent 输出的间隔违反单调性，Then 系统降级为 FSRS 结果并记录告警。
- Given 相同输入，Then 排程结果可复现（Agent 温度 0 + 确定性护栏）。

#### FR-4.3 离线复习 `P0`

> **关键约束：客户端不参与排程。** 离线复习是在**服务端已排期**的基础上消费队列，不是本地重新计算。

- 客户端预下载未来 7 天的复习队列（含卡片内容与图片）。
- 离线时按队列顺序复习，评分写入**本地 Outbox**，**不计算** `due_at`。
- 联网后按序重放，服务端 Agent 重新排程。
- 重放使用幂等键（`review_id` 由客户端生成 UUID），服务端去重。
- 冲突策略：以服务端为准，客户端本地状态回滚并提示。

**验收标准**

- Given 飞行模式下完成 15 张复习，When 恢复网络，Then 15 条记录在 30 秒内同步完成，服务端完成重排程。
- Given 同一 `review_id` 重复提交，Then 服务端只记录一次。
- Given 离线时用户进入「自由浏览」，Then **不产生**任何 `review_log`，排程不受影响。

#### FR-4.4 自由浏览与刷卡片 `P0`

用户可以**不进入复习会话**，直接浏览卡片集里的任意卡片：

- 入口：卡片集详情页点击任意卡片。
- 支持左右翻页（上一张 / 下一张）、随机、按标签筛选。
- 明文与暗文**同时展示**（浏览模式），不做自检遮罩。
- **不记录评分、不影响排程**，仅记录「浏览过」。
- 可随时从浏览模式「开始复习」当前卡片集。

**验收标准**

- Given 用户浏览 50 张卡片，Then 这 50 张卡片的 `due_at` 均不变。
- Given 用户在浏览模式点击「开始复习」，Then 进入复习会话，队列为服务端排程结果。

#### FR-4.5 卡片页面 `P0`

> 依据 [卡片页面设计稿](卡片页面.png) 实现。

单页滚动布局，自上而下：

| 区域 | 内容 | 说明 |
| --- | --- | --- |
| 顶部栏 | 返回 · 小星星 | 小星星为评分控件（1–4 星，映射 忘记/困难/良好/简单） |
| 卡片明文 | 正面文本 | 复习模式下为问题/提示 |
| 卡片暗文 | 背面文本 | 复习模式下默认遮罩，翻页揭示；浏览模式下直接展示 |
| 图片 | 卡片配图 | 可选，支持点击放大 |
| Agent 分析/解惑区 | 内联对话 | 基于当前卡片上下文答疑，回答可引用其他卡片 |
| 选项/回答输入/提问输入区 | 输入区 | 支持选择题选项、简答输入、提问输入三种模式 |
| 翻页 | 上一张 / 下一张 | 也可用左右滑动 |

**验收标准**

- Given 复习模式，When 卡片加载，Then 暗文被遮罩，点击「翻页」后揭示。
- Given 浏览模式，Then 明文与暗文同时可见。
- Given 用户在 Agent 分析/解惑区提问，Then 回答基于当前卡片 + 所属卡片集知识库，并标注引用。
- Given 用户点击小星星某档，Then 记录评分并进入下一张。
- Given 卡片有图片，Then 图片在暗文下方展示，点击可全屏查看。

#### FR-4.6 学习统计 `P1`

- 卡片集维度：累计复习数、正确率、连续打卡天数、未来 30 天到期分布。
- 全局维度：总学习时长、总卡片数、活跃天数。
- 排程维度：当前模式、平均间隔、预估考试前覆盖率。

### E5 长期学习计划

> **与 E4 排程的分工**：
>
> - **E4 排程 Agent** 决定「**这张卡片下次什么时候复习**」——细粒度、每卡一条、后台异步。
> - **E5 计划 Agent** 决定「**今天/本周学什么**」——粗粒度、按天聚合、需要用户确认。
>
> 计划依赖排程的输出（`due_at` 分布），二者顺序执行。**两者都不在客户端计算。**

#### FR-5.1 计划生成 `P0`

- 用户设定：目标（如「3 个月内通过考试」）、截止日期、每日可用时长（15/30/45/60 分钟）。
- Agent 汇总所有卡片集的到期情况，生成**未来 7 天**的每日任务：
  - 每日复习卡片数
  - 每日新卡数
  - 预计耗时
  - 一句话理由（可解释性）
- 计划以「建议」形式呈现，用户点击「同意」后生效。

**验收标准**

- Given 用户设定每日 30 分钟、截止日期 90 天后，When 生成计划，Then 返回 7 天任务，每日预计耗时 ≤ 35 分钟（含 15% 缓冲）。
- Given 到期卡片总量超出时间预算，Then 计划明确标注「今日无法完成全部到期卡片」，并给出优先级排序理由。
- Given 用户点击「调整」，Then 可修改每日时长并重新生成。

#### FR-5.2 计划执行与追踪 `P0`

- 首页展示今日任务卡片：进度环（已完成/总数）、预计剩余时间。
- 完成全部任务后展示「今日完成」状态。
- 计划偏差超过 2 天未完成时，Agent 主动提示「需要重新规划吗？」

#### FR-5.3 每日推送 `P1`

- 每日在用户设定的时间（默认 20:00）推送复习提醒。
- 推送内容包含：待复习数量、预计耗时。
- 支持静默时段（22:00–08:00 不推送）。
- 用户可关闭推送。

### E6 知识库与答疑

#### FR-6.1 知识库构建 `P0`

- 每个卡片集自动构建知识库（可关闭）。
- 切分策略：**以卡片为最小单元**，每张卡片生成一个 chunk（明文 + 暗文 + 标签）。
- 同时保留资料原文 chunk（按语义段落切分，512 token，重叠 64 token），用于回答卡片未覆盖的问题。
- 嵌入模型：`bge-m3`（1024 维），存储于 pgvector。
- 卡片新增/编辑/删除时，**增量更新**索引（异步，5 分钟内生效）。

**验收标准**

- Given 卡片集有 500 张卡片，When 首次构建知识库，Then 10 分钟内完成，状态可查询。
- Given 用户编辑一张卡片，Then 5 分钟内该卡片向量更新。
- Given 用户删除卡片集，Then 其向量数据被清理。

#### FR-6.2 答疑对话 `P0`

- 全局助手入口（底部导航「助手」Tab）。
- 支持多轮对话，会话可保存与重命名。
- 回答必须**引用来源卡片**（可点击跳转到卡片详情）。
- 流式输出（SSE），首 token 延迟 ≤ 2 秒（P90）。
- 支持指定范围：全部卡片集 / 某个卡片集。

**验收标准**

- Given 用户问「光合作用的暗反应发生在哪里」，When 卡片集中有相关卡片，Then 回答包含引用卡片链接。
- Given 卡片集中无相关内容，Then 明确说明「你的卡片集中没有相关内容」，并询问是否使用通用知识回答。
- Given 用户点击引用卡片，Then 跳转到卡片详情页。

#### FR-6.3 卡片内联答疑 `P0`

> 对应设计稿中的「Agent 分析/解惑区」。**答疑不是独立 Tab 的专属能力**，卡片页面内嵌同一条链路。

- 卡片页面（FR-4.5）内置可折叠的「Agent 分析/解惑区」。
- 上下文自动注入：当前卡片明文 + 暗文 + 所属卡片集。
- 默认折叠，点击才请求，避免打断复习心流。
- 回答可引用**其他卡片**，点击跳转。
- 支持「分析这张卡片」快捷指令（解释考点、拆解记忆点、生成类比）。

**验收标准**

- Given 用户在卡片页面点击「分析这张卡片」，Then 返回基于该卡片的分析，且不重复卡片原文。
- Given 内联答疑的上下文包含当前卡片，When 用户问「这张卡片和哪张相关」，Then 能检索同卡片集的其他卡片并引用。
- Given 用户未展开答疑区，Then **不产生**任何 LLM 调用。

#### FR-6.4 制卡联动 `P1`

- 对话中用户说「帮我把这个知识点做成卡片」，Agent 可触发制卡流程，进入草稿预览。

### E8 通用卡片系统扩展点

> MVP 只实现 `memory` 一种卡片类型，但**所有接口必须按多类型设计**，否则后续无法扩展。

#### FR-8.1 卡片类型注册 `P0`

- 后端维护卡片类型注册表，每种类型定义：
  - `type_id`（如 `memory`）
  - 数据 Schema（卡片字段结构）
  - 生成工作流标识
  - 运行器标识（如 `fsrs`）
  - 默认集合配置
- 前端维护对应的渲染器注册表。

**验收标准**

- Given 新增一种卡片类型，Then 只需注册类型定义与渲染器，不需要修改核心 CRUD 代码。
- Given 卡片集绑定的类型不存在，Then 返回明确错误而非 500。

#### FR-8.2 集合配置 `P0`

- 卡片集配置以 JSON 存储，包含 `card_type`、`display`、`runner`、`generator`、`knowledge` 五个区块。
- 配置有 Schema 校验，非法配置拒绝保存。

#### FR-8.3 统一运行入口 `P1`

- 存在一个「运行调度器」接口，按卡片集类型分发到对应运行器。
- MVP 只注册 `fsrs` 运行器。

## 6. 非功能需求

### 6.1 性能

| 指标 | 目标 |
| --- | --- |
| App 冷启动 | ≤ 2.5s（中端 Android） |
| 卡片列表首屏 | ≤ 800ms（本地缓存命中 ≤ 200ms） |
| 复习翻页 | ≤ 100ms |
| 搜索响应 | P95 ≤ 500ms |
| API 响应 | P95 ≤ 300ms（不含 LLM） |
| 答疑首 token | P90 ≤ 2s |
| 制卡 30 张 | ≤ 3 分钟 |

### 6.2 可用性与离线

- 复习、卡片浏览、搜索（本地缓存范围内）**完全离线可用**。
- 离线队列自动重放，失败指数退避，最多重试 5 次。
- 服务可用性目标：MVP 阶段 99%（非 SLA 承诺）。

### 6.3 安全

- 传输：全链路 HTTPS / TLS 1.3。
- 密码：Argon2id 哈希。
- Token：Access Token 15 分钟，Refresh Token 30 天，支持轮换与撤销。
- 数据隔离：所有查询强制带 `user_id` 条件，通过行级安全（RLS）兜底。
- 上传文件：类型白名单 + 大小限制 + 病毒扫描（P1）。
- 限流：登录 5 次/分钟，LLM 接口 20 次/分钟/用户。

### 6.4 隐私与合规

- 用户资料（PDF/图片）**不用于模型训练**。
- 提供账号注销与数据导出（JSON）。
- 明确告知用户资料会被发送给第三方 LLM 服务商。
- 遵循《个人信息保护法》最小必要原则。

### 6.5 成本

- 单用户单月 LLM 成本目标 ≤ ¥3（按 30 张制卡 + 100 轮答疑估算）。
- 嵌入计算优先自托管（TEI + bge-m3），避免按 token 计费。

### 6.6 可观测性

- 结构化日志（JSON），带 `trace_id` / `user_id` / `request_id`。
- LLM 调用全链路追踪（Langfuse），记录 prompt、token 数、延迟、成本。
- 错误上报（Sentry）。
- 核心业务指标埋点。

### 6.7 兼容性

- iOS 15+，Android 8.0+（API 26+）。
- 屏幕适配：4.7" – 7.0"。

## 10. 风险与开放问题

### 10.1 风险

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | 生成卡片质量不稳定（幻觉、碎片化） | 高 | 严格 prompt + 质检去重 + 强制人工确认；建立评测集 |
| R2 | LLM 成本超预期 | 中 | 分级模型（生成用强模型、质检用弱模型）；嵌入自托管；配额限制 |
| R3 | 仅移动端导致「批量制卡」体验差 | 中 | 支持多文件批量导入；草稿箱支持批量勾选；**不引入第二端**，通过交互优化解决 |
| R4 | 离线同步冲突 | 中 | 幂等键 + 服务端权威 + 冲突提示 |
| R5 | **Agent 排程不可解释 / 不稳定** | 高 | 确定性护栏（单调性、上下界、预算）+ 每张卡片附理由 + 违规降级 FSRS + 温度 0 |
| R6 | 资料解析（PDF/图片）成功率低 | 中 | 多引擎兜底；失败可重试；P1 加 OCR |
| R7 | 合规风险（用户上传版权资料） | 中 | 用户协议明确责任；不公开分享 |
| R8 | 离线队列过期（预下载 7 天，用户 10 天没联网） | 低 | 队列过期时提示「需联网更新排期」，允许继续消费旧队列但标注「可能不是最优」 |
| R9 | 卡片内联答疑延迟高，打断复习心流 | 中 | 答疑区默认折叠；点击才请求；流式输出；缓存常见问题 |

## 11. 里程碑

| 阶段 | 周期 | 交付物 | 验收标准 |
| --- | --- | --- | --- |
| M0 技术验证 | 1 周 | 技术栈打通：Flutter 登录 + FastAPI + Postgres + 一次 LLM 调用 | 端到端跑通 |
| M1 卡片基础 | 2 周 | E1 + E2 + E8 骨架 | 可手动建卡、管理、搜索 |
| M2 制卡流水线 | 2 周 | E3 | 导入 PDF 生成 30 张卡片并确认落库 |
| M3 卡片页面与复习会话 | 2 周 | E4（FR-4.1 / 4.4 / 4.5，前端为主） | 卡片页面按设计稿还原；复习会话可跑通；自由浏览不影响排程 |
| M4 排程 Agent 与离线 | 2 周 | E4（FR-4.2 / 4.3） | 三种学习模式可切换；离线队列可重放；护栏降级生效 |
| M5 计划与答疑 | 2 周 | E5 + E6 | Agent 计划 + 卡片内联答疑 + 引用式回答 |
| M6 打磨与内测 | 2 周 | E7 + 埋点 + 性能优化 | 20 人内测，指标达标 |

**MVP 总周期：约 13 周（M0–M6 串行，未含缓冲；建议按 14 周排期留 1 周缓冲）**

> **为什么 M3/M4 拆开**：卡片页面（前端）与排程 Agent（后端）依赖方向相反，可并行但不宜混在一个里程碑验收。M3 用**假数据**跑通页面与交互，M4 再接真实排程。

## 附录 A：术语表

| 术语 | 说明 |
| --- | --- |
| 卡片（Card） | 最小内容单元，MVP 为「明文 / 暗文」问答对 |
| 卡片明文 | 卡片正面文本，复习时作为问题/提示 |
| 卡片暗文 | 卡片背面文本，复习时默认遮罩，翻页揭示 |
| 卡片集（Deck） | 卡片的容器，绑定一种卡片类型 |
| 文件夹（Folder） | 卡片集的单层分类 |
| 卡片类型（Card Type） | 可插拔的能力包，定义显示/运行/生成/知识库方式 |
| 草稿（Draft） | Agent 生成但未经用户确认的卡片 |
| 排程 Agent（Scheduler Agent） | 服务端负责决定每张卡片下次复习时间的 Agent |
| 学习模式（Learner Mode） | 标准 / 考试冲刺 / 强记忆 / 自定义，驱动排程策略 |
| 确定性护栏（Guardrail） | 校验 Agent 排程输出的代码层约束，违反则降级 FSRS |
| FSRS | Free Spaced Repetition Scheduler，记忆曲线算法，作为护栏兜底 |
| 保留率（Retention） | 期望在到期时仍能回忆起的概率 |
| 自由浏览（Free Browse） | 不进入复习、不影响排程的卡片翻阅模式 |
| Outbox | 客户端离线写队列 |
| RAG | 检索增强生成 |
