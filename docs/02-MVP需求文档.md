## 1. 背景与问题

### 1.1 现状

面对大量记忆性学习任务的用户（考研、考证、语言学习、医学/法条等专业记忆），当前主流方案是 Anki 一类的记忆卡片工具。这类工具的核心缺陷是**制卡成本高、卡片来源受限、学习计划需要用户自己维护**：

- **制卡重**：从 PDF、网页、课件里提炼知识点并拆成问答对，是纯粹的重复劳动，用户往往在制卡阶段就放弃。
- **来源窄**：特定领域（如某本教材、某份讲义）没有现成卡片库，用户只能手工录入。
- **计划负担**：复习节奏、每日任务量、优先级全部由用户自己判断，缺乏一个「替我做决定」的角色。
- **答疑割裂**：用户遇到不懂的卡片，需要跳出应用去搜索，学习上下文断裂。

### 1.2 机会

大模型具备**信息抽取、结构化生成、规划与答疑**能力，恰好覆盖上述四个缺陷。把 Agent 放进卡片产品的核心链路，可以让「资料 → 卡片 → 计划 → 复习 → 答疑」形成闭环。

### 1.3 更远的判断

卡片不应只承载知识点。它可以是日程、回忆、灵感。如果从第一天起就把「卡片类型」做成可插拔的能力包（显示格式 / 运行形式 / 生成工作流 / 知识库建立方式），产品就能从「记忆卡片工具」长成「通用卡片助手」。**这是本项目与 Anki 类产品的根本分野，也是 MVP 架构必须提前付出的成本。**

## 2. 产品定位

### 2.1 一句话定位

> **CardSharp 是一个可拓展的 AI 卡片助手：用 Agent 把用户的资料变成可运行的卡片集合，并用长期学习计划驱动用户持续记忆。**

### 2.2 核心价值主张

| # | 价值 | 对应痛点 |
| --- | --- | --- |
| V1 | **零成本制卡**：导入资料，Agent 生成可复习的卡片集，用户只做确认与微调 | 制卡重 |
| V2 | **Agent 排程**：不需要用户自己决定今天学什么，Agent 结合记忆曲线与卡片质量给出计划，用户一键同意 | 计划负担 |
| V3 | **卡片即知识库**：卡片集同时是可检索的知识库，答疑助手基于「你自己的卡片」回答，而不是通用模型泛泛而谈 | 答疑割裂 |

### 2.3 目标用户（MVP 聚焦）

**主画像：备考型学习者**

- 年龄 18–30，学生或职场转行者
- 手上有明确的学习资料（PDF 教材、课件、网课笔记、网页文章）
- 每天可投入 20–60 分钟碎片时间，主要在手机上
- 有明确的考试/认证截止日期
- 用过或听说过 Anki，但被制卡成本劝退

**次画像（MVP 覆盖但不重点优化）**

- 需要记录灵感的写作者
- 长期写日记/随笔的人

### 2.4 非目标（MVP 明确不做）

- ❌ 不做卡片社区、发布、打卡、卡片仓库
- ❌ 不做 AI 配图生成
- ❌ 不做桌面端原生应用（Windows / macOS）
- ❌ 不做多人协作 / 共享卡片集
- ❌ 不做复杂层级文件夹（MVP 只做单层）
- ❌ 不做插件市场 / 用户自定义 Agent

> 关于「电脑制卡、同步到移动端」这一原始设想：MVP 收敛为**仅移动端**，制卡入口在手机（拍照/相册/文件/链接）。Flutter 选型使后续补齐 Web 制卡台与桌面端的边际成本很低，该能力排入 P1（见 §11）。

## 3. 核心场景（Jobs To Be Done）

### JTBD-1 把资料变成卡片

> 当我手上有一份 60 页的 PDF 讲义，我想把它变成能复习的卡片，这样我不用逐页手抄。

**关键约束**：我不能接受 Agent 直接写入几百张烂卡片。我需要**先看草稿、再决定**。

### JTBD-2 每天知道该学什么

> 当我打开 App，我想知道今天该复习哪些卡片，这样我不用自己算记忆曲线。

**关键约束**：计划必须是**可解释**的（为什么今天这些卡片），且**可调整**（今天没时间，能不能少一点）。

### JTBD-3 复习时自检

> 当我进入复习，我想看到卡片正面、自己回忆、翻面核对、然后诚实评分。

**关键约束**：必须**离线可用**，地铁上没信号也要能复习。

### JTBD-4 遇到不懂就问

> 当我对一张卡片的内容有疑问，我想直接问助手，并且它的回答基于我自己的卡片集。

**关键约束**：回答要**引用来源卡片**，否则我无法判断可信度。

### JTBD-5 管理我的卡片

> 当我有十几个卡片集，我想分类、打标签、搜索、编辑，这样我找得到、改得动。

## 4. 需求总览

| Epic | 名称 | 优先级 | 说明 |
| --- | --- | --- | --- |
| E1 | 账号与设备 | P0 | 注册登录、设备管理、推送令牌 |
| E2 | 卡片与集合管理 | P0 | 文件夹、卡片集、卡片 CRUD、标签、搜索 |
| E3 | 制卡流水线 | P0 | 资料导入 → Agent 生成 → 预览确认 → 落库 |
| E4 | 记忆训练 | P0 | 复习会话、翻面自检、FSRS 评分、离线队列 |
| E5 | 长期学习计划 | P0 | Agent 规划、计划确认、每日推送、进度追踪 |
| E6 | 知识库与答疑 | P0 | 卡片集向量化、RAG 检索、引用式回答、流式输出 |
| E7 | 通知与提醒 | P1 | 复习提醒、计划提醒、静默时段 |
| E8 | 通用卡片系统扩展点 | P0 | 卡片类型注册、集合配置、运行器接口 |

## 5. 详细功能需求

### E1 账号与设备

#### FR-1.1 注册与登录 `P0`

- 支持**邮箱 + 密码**与**手机号 + 验证码**两种方式。
- 登录态使用 JWT（Access Token 短期 + Refresh Token 长期），Refresh Token 可撤销。
- 支持「退出登录」与「退出所有设备」。

**验收标准**

- Given 未注册邮箱，When 提交注册，Then 创建账号并自动登录，收到验证邮件。
- Given 已登录用户，When 在第二台设备登录，Then 两台设备同时有效，设备列表可见两条记录。
- Given 用户在设备 A 退出所有设备，When 设备 B 发起请求，Then 返回 401 并跳转登录页。

#### FR-1.2 设备与推送令牌 `P1`

- 记录设备型号、系统版本、推送令牌、最后活跃时间。
- 推送令牌变更时自动更新。

---

### E2 卡片与集合管理

#### FR-2.1 单层文件夹 `P0`

- 用户可创建、重命名、删除、排序文件夹。
- 文件夹**只有一层**，不支持嵌套。
- 删除文件夹时，其下卡片集移动到「未分类」，不级联删除。

**验收标准**

- Given 存在文件夹「考研政治」，When 用户删除该文件夹，Then 文件夹消失，原卡片集出现在「未分类」，卡片本身不受影响。

#### FR-2.2 卡片集（Deck）`P0`

- 卡片集是卡片的容器，绑定**一个卡片类型**（MVP 固定为 `memory`）。
- 卡片集包含：标题、描述、封面色、所属文件夹、类型配置（JSON）、统计信息（总卡片数、今日待复习数）。
- 支持创建、重命名、删除、移动到文件夹。

**验收标准**

- Given 用户创建卡片集时未指定类型，Then 默认 `memory`。
- Given 卡片集被删除，When 用户确认删除，Then 卡片集与其下所有卡片进入回收站，30 天后物理删除。

#### FR-2.3 卡片 CRUD `P0`

- 卡片字段（`memory` 类型）：正面、背面、可选图片、可选标签、备注。
- 支持手动新建、编辑、删除、批量移动、批量打标签。
- 编辑卡片内容时，**不重置**其复习进度（stability / difficulty 保留），但记录一次内容变更。

**验收标准**

- Given 一张已复习 10 次的卡片，When 用户修改背面文本并保存，Then 卡片内容更新，`due_at` 与 `stability` 保持不变。

#### FR-2.4 标签与搜索 `P0`

- 用户可自定义标签，标签为全局维度（跨卡片集）。
- 搜索支持：全局搜索 / 指定卡片集内搜索。
- 搜索范围：卡片正面、背面、标签、所属卡片集名称。
- 中文搜索使用 `pg_trgm` + `tsvector` 混合，支持模糊匹配。

**验收标准**

- Given 用户输入「唯物」，Then 返回正面或背面包含该词的卡片，命中词高亮。
- Given 用户在卡片集内搜索，Then 结果限定在该卡片集。

#### FR-2.5 回收站 `P1`

- 删除的卡片/卡片集进入回收站，支持恢复与彻底删除。
- 30 天自动清理。

### E3 制卡流水线

> **这是 MVP 最核心、最复杂的链路。** 设计原则：Agent 产出**草稿**，用户**确认**后才落库。

#### FR-3.1 资料导入 `P0`

支持的资料类型：

| 类型 | 入口 | 处理方式 |
| --- | --- | --- |
| PDF | 文件选择器 | 文本层抽取；扫描件走 OCR（P1） |
| 网页链接 | 粘贴 URL | 正文抽取（Readability 算法） |
| 图片 | 拍照 / 相册 | 视觉模型 OCR + 理解 |
| 纯文本 | 直接粘贴 | 直接使用 |

- 单文件上限 50 MB，单次导入上限 5 个文件。
- 资料原件存入对象存储，与卡片集关联。
- 抽取失败时给出明确错误提示，允许重试。

**验收标准**

- Given 用户上传 30 页 PDF，When 解析完成，Then 显示页数与抽取字符数，可进入生成。
- Given 上传加密 PDF，Then 提示「文件受密码保护，无法解析」。
- Given 上传纯图片 PDF，Then 提示「未检测到文本层，将使用 OCR」（P1）。

#### FR-3.2 生成配置 `P0`

用户可配置：

- 生成数量（10 / 20 / 30 / 自定义，上限 100）
- 难度（基础 / 标准 / 进阶）
- 语言（跟随资料 / 中文 / 英文）
- 是否包含图片（MVP 固定关闭）
- 补充指令（自由文本，如「重点考查时间线」）

#### FR-3.3 生成过程 `P0`

- 生成任务异步执行，前端展示**流式进度**（阶段 + 百分比 + 已生成卡片数）。
- 阶段：`解析资料 → 抽取知识点 → 生成卡片 → 去重与质检 → 待确认`
- 支持取消任务。
- 单次生成超时 10 分钟，超时标记失败并保留已生成部分。

**验收标准**

- Given 生成任务进行中，When 用户退出页面再进入，Then 任务仍在后台运行且进度正确。
- Given 用户点击取消，Then 任务停止，已生成的卡片草稿保留在草稿箱。
- Given 生成失败，Then 展示失败原因与「重试」按钮，不消耗用户配额。

#### FR-3.4 草稿预览与确认 `P0`

- 以卡片列表形式展示草稿，支持**逐张编辑**（正面/背面/标签）。
- 支持**逐张删除**、**全选/反选**。
- 显示质检结果：重复卡片（与已有卡片相似度高）标记为「疑似重复」，默认不勾选。
- 用户点击「导入到卡片集」后，选中的卡片才真正落库。
- 落库时初始化复习状态为「新卡」，`due_at = 现在`。

**验收标准**

- Given 生成 30 张草稿，When 用户取消勾选 5 张并确认，Then 卡片集新增 25 张卡片，草稿箱清空。
- Given 草稿与已有卡片相似度 > 0.9，Then 默认不勾选并标注「疑似重复」。
- Given 用户关闭 App 未确认，Then 草稿保留 7 天，可在「草稿箱」继续。

#### FR-3.5 生成质量要求 `P0`

- 卡片必须**自包含**：不依赖上下文即可理解（不使用「上文提到的」「该概念」等指代）。
- 每张卡片只考查**一个**知识点。
- 正面为问题/提示，背面为答案，长度限制：正面 ≤ 200 字，背面 ≤ 500 字。
- 禁止生成「是/否」型低价值卡片。

### E4 记忆训练

#### FR-4.1 复习会话 `P0`

- 入口：卡片集详情页「开始复习」/ 首页「今日任务」。
- 会话队列 = 到期卡片（`due_at <= now`）+ 新卡（受每日新卡上限约束）。
- 卡片正面展示 → 用户回忆 → 点击「显示答案」→ 展示背面 → 用户评分。
- 支持手势：左滑 = 忘记，右滑 = 记住（可配置）。
- 会话结束展示统计：复习张数、正确率、耗时、下次复习时间。

**验收标准**

- Given 今日有 20 张到期卡片，When 用户开始复习，Then 队列为 20 张，顺序按 `due_at` 升序。
- Given 会话中途退出，Then 进度已保存，重新进入从断点继续。
- Given 用户对一张卡片评分「忘记」，Then 该卡片在本会话中会再次出现（间隔 ≥ 5 张）。

#### FR-4.2 评分与排程 `P0`

- 四档评分：`忘记(1)` / `困难(2)` / `良好(3)` / `简单(4)`。
- 排程算法：**FSRS**（Free Spaced Repetition Scheduler），确定性计算，不经过 LLM。
- 每张卡片维护：`stability`、`difficulty`、`due_at`、`reps`、`lapses`、`last_review_at`。
- 目标保留率默认 0.9，用户可在卡片集设置中调整（0.8–0.95）。

**验收标准**

- Given 一张新卡，When 用户评分「良好」，Then `due_at` 落在 1 天后（±2 小时）。
- Given 一张卡片连续评分「简单」，Then 复习间隔单调递增。
- Given 用户评分「忘记」，Then `lapses + 1`，`stability` 显著下降。
- Given 相同输入序列，Then 排程结果**完全可复现**（纯函数）。

#### FR-4.3 离线复习 `P0`

- 复习会话完全离线可用（卡片内容预下载到本地）。
- 离线产生的复习记录进入**本地 Outbox 队列**，联网后按序重放。
- 重放使用幂等键（`review_id` 由客户端生成 UUID），服务端去重。
- 冲突策略：以服务端为准，客户端本地状态回滚并提示。

**验收标准**

- Given 飞行模式下完成 15 张复习，When 恢复网络，Then 15 条记录在 30 秒内同步完成，服务端状态正确。
- Given 同一 `review_id` 重复提交，Then 服务端只记录一次。

#### FR-4.4 学习统计 `P1`

- 卡片集维度：累计复习数、正确率、连续打卡天数、未来 30 天到期分布。
- 全局维度：总学习时长、总卡片数、活跃天数。

### E5 长期学习计划

> **设计原则：排程（什么时候复习哪张卡）由 FSRS 确定性算法负责；Agent 只负责「策略层」——时间预算分配、跨卡片集优先级、目标拆解与解释。** 不让 LLM 决定记忆曲线。

#### FR-5.1 计划生成 `P0`

- 用户设定：目标（如「3 个月内通过考试」）、截止日期、每日可用时长（15/30/45/60 分钟）。
- Agent 汇总所有卡片集的到期情况，生成**未来 7 天**的每日任务：
  - 每日复习卡片数
  - 每日新卡数
  - 预计耗时
  - 一句话理由（可解释性）
- 计划以「建议」形式呈现，用户点击「同意」后生效。

**验收标准**

- Given 用户设定每日 30 分钟、截止日期 90 天后，When 生成计划，Then 返回 7 天任务，每日预计耗时 ≤ 35 分钟（含 15% 缓冲）。
- Given 到期卡片总量超出时间预算，Then 计划明确标注「今日无法完成全部到期卡片」，并给出优先级排序理由。
- Given 用户点击「调整」，Then 可修改每日时长并重新生成。

#### FR-5.2 计划执行与追踪 `P0`

- 首页展示今日任务卡片：进度环（已完成/总数）、预计剩余时间。
- 完成全部任务后展示「今日完成」状态。
- 计划偏差超过 2 天未完成时，Agent 主动提示「需要重新规划吗？」

#### FR-5.3 每日推送 `P1`

- 每日在用户设定的时间（默认 20:00）推送复习提醒。
- 推送内容包含：待复习数量、预计耗时。
- 支持静默时段（22:00–08:00 不推送）。
- 用户可关闭推送。

### E6 知识库与答疑

#### FR-6.1 知识库构建 `P0`

- 每个卡片集自动构建知识库（可关闭）。
- 切分策略：**以卡片为最小单元**，每张卡片生成一个 chunk（正面 + 背面 + 标签）。
- 同时保留资料原文 chunk（按语义段落切分，512 token，重叠 64 token），用于回答卡片未覆盖的问题。
- 嵌入模型：`bge-m3`（1024 维），存储于 pgvector。
- 卡片新增/编辑/删除时，**增量更新**索引（异步，5 分钟内生效）。

**验收标准**

- Given 卡片集有 500 张卡片，When 首次构建知识库，Then 10 分钟内完成，状态可查询。
- Given 用户编辑一张卡片，Then 5 分钟内该卡片向量更新。
- Given 用户删除卡片集，Then 其向量数据被清理。

#### FR-6.2 答疑对话 `P0`

- 全局助手入口（底部导航「助手」Tab）。
- 支持多轮对话，会话可保存与重命名。
- 回答必须**引用来源卡片**（可点击跳转到卡片详情）。
- 流式输出（SSE），首 token 延迟 ≤ 2 秒（P90）。
- 支持指定范围：全部卡片集 / 某个卡片集。

**验收标准**

- Given 用户问「光合作用的暗反应发生在哪里」，When 卡片集中有相关卡片，Then 回答包含引用卡片链接。
- Given 卡片集中无相关内容，Then 明确说明「你的卡片集中没有相关内容」，并询问是否使用通用知识回答。
- Given 用户点击引用卡片，Then 跳转到卡片详情页。

#### FR-6.3 制卡联动 `P1`

- 对话中用户说「帮我把这个知识点做成卡片」，Agent 可触发制卡流程，进入草稿预览。

#### FR-7.1 推送通道 `P1`

### E8 通用卡片系统扩展点

> MVP 只实现 `memory` 一种卡片类型，但**所有接口必须按多类型设计**，否则后续无法扩展。

#### FR-8.1 卡片类型注册 `P0`

- 后端维护卡片类型注册表，每种类型定义：
  - `type_id`（如 `memory`）
  - 数据 Schema（卡片字段结构）
  - 生成工作流标识
  - 运行器标识（如 `fsrs`）
  - 默认集合配置
- 前端维护对应的渲染器注册表。

**验收标准**

- Given 新增一种卡片类型，Then 只需注册类型定义与渲染器，不需要修改核心 CRUD 代码。
- Given 卡片集绑定的类型不存在，Then 返回明确错误而非 500。

#### FR-8.2 集合配置 `P0`

- 卡片集配置以 JSON 存储，包含 `card_type`、`display`、`runner`、`generator`、`knowledge` 五个区块。
- 配置有 Schema 校验，非法配置拒绝保存。

#### FR-8.3 统一运行入口 `P1`

- 存在一个「运行调度器」接口，按卡片集类型分发到对应运行器。
- MVP 只注册 `fsrs` 运行器。

## 6. 非功能需求

### 6.1 性能

| 指标 | 目标 |
| --- | --- |
| App 冷启动 | ≤ 2.5s（中端 Android） |
| 卡片列表首屏 | ≤ 800ms（本地缓存命中 ≤ 200ms） |
| 复习翻面 | ≤ 100ms |
| 搜索响应 | P95 ≤ 500ms |
| API 响应 | P95 ≤ 300ms（不含 LLM） |
| 答疑首 token | P90 ≤ 2s |
| 制卡 30 张 | ≤ 3 分钟 |

### 6.2 可用性与离线

- 复习、卡片浏览、搜索（本地缓存范围内）**完全离线可用**。
- 离线队列自动重放，失败指数退避，最多重试 5 次。
- 服务可用性目标：MVP 阶段 99%（非 SLA 承诺）。

### 6.3 安全

- 传输：全链路 HTTPS / TLS 1.3。
- 密码：Argon2id 哈希。
- Token：Access Token 15 分钟，Refresh Token 30 天，支持轮换与撤销。
- 数据隔离：所有查询强制带 `user_id` 条件，通过行级安全（RLS）兜底。
- 上传文件：类型白名单 + 大小限制 + 病毒扫描（P1）。
- 限流：登录 5 次/分钟，LLM 接口 20 次/分钟/用户。

### 6.4 隐私与合规

- 用户资料（PDF/图片）**不用于模型训练**。
- 提供账号注销与数据导出（JSON）。
- 明确告知用户资料会被发送给第三方 LLM 服务商。
- 遵循《个人信息保护法》最小必要原则。

### 6.5 成本

- 单用户单月 LLM 成本目标 ≤ ¥3（按 30 张制卡 + 100 轮答疑估算）。
- 嵌入计算优先自托管（TEI + bge-m3），避免按 token 计费。

### 6.6 可观测性

- 结构化日志（JSON），带 `trace_id` / `user_id` / `request_id`。
- LLM 调用全链路追踪（Langfuse），记录 prompt、token 数、延迟、成本。
- 错误上报（Sentry）。
- 核心业务指标埋点。

### 6.7 兼容性

- iOS 15+，Android 8.0+（API 26+）。
- 屏幕适配：4.7" – 7.0"。

## 9. 成功指标

### 9.2 核心指标

| 指标 | 定义 | MVP 目标 |
| --- | --- | --- |

| 周复习频次 | 人均每周复习会话数 | ≥ 3 |
| 答疑使用率 | 使用过答疑的用户占比 | ≥ 30% |
| 计划采纳率 | 同意 Agent 计划的用户 / 生成过计划的用户 | ≥ 60% |

| 指标 | 目标 |
| --- | --- |

| 卡片重复率 | ≤ 10% |
| 答疑引用准确率 | ≥ 85%（人工抽检） |
| 崩溃率 | ≤ 0.5% |

## 10. 风险与开放问题

### 10.1 风险

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | 生成卡片质量不稳定（幻觉、碎片化） | 高 | 严格 prompt + 质检去重 + 强制人工确认；建立评测集 |
| R2 | LLM 成本超预期 | 中 | 分级模型（生成用强模型、质检用弱模型）；嵌入自托管；配额限制 |
| R3 | 仅移动端导致「批量制卡」体验差 | 中 | 支持多文件批量导入；P1 补 Web 制卡台 |
| R4 | 离线同步冲突 | 中 | 幂等键 + 服务端权威 + 冲突提示 |
| R5 | 用户不理解 FSRS，觉得排程「不合理」 | 中 | 提供「为什么现在复习」的解释；允许手动调整 |
| R6 | 资料解析（PDF/图片）成功率低 | 中 | 多引擎兜底；失败可重试；P1 加 OCR |
| R7 | 合规风险（用户上传版权资料） | 中 | 用户协议明确责任；不公开分享 |
