## 卡片生成、管理助手

### 目标用户

面对大量记忆性学习任务的各领域学习者、需要记录灵感的写作者、喜欢写日记/随笔的人、还有更多场景可以发掘

### 要解决的问题

先从记忆卡片说起：目前市面上的记忆卡片产品大多难以满足用户定制化的学习记忆需求，同时对于特定的领域，记忆卡片的来源有限、搜集不便。这对这一场景本项目计划利用 agent 的决策、生成能力帮助用户快速搭建生成定制化的记忆卡片，MVP 在移动端完成制卡、管理与复习

这个项目不应只拘泥于记忆卡片这一特定场景：卡片不只是知识点的承载体，亦可以是日程、回忆、灵感的承载体；通过组织卡片、将不同的卡片集和绑定到不同的组织形式（知识库、工作流、数据库、skills）上，让这个应用具备更多的泛用性

### 功能需求

核心功能是卡片组织成集合、单张卡片展示、卡片集合运行形式、卡片生成、卡片集合知识库建立方式；每一套卡片集合都有特有的显示格式、运行形式、生成工作流、知识库建立方式；
同时存在一个通用agent用于回答用户和各个卡片集合有关的问题（去查询知识库）

目前先考虑一个最通用的场景：记忆卡片（类比 Anki）
对于记忆卡片集合：
显示格式：用于辅助自检记忆任务的卡片显示；
运行形式：向用户推送 Agent 规划好的记忆任务，用户同意后按照为用户提供自检记忆服务（服务端 Agent 根据学习目标、考试日期、记忆能力、卡片质量和记忆曲线安排记忆计划；客户端离线消费已排期队列，也可自由浏览卡片）
生成工作流：agent 协助快速生成记忆卡片（信息搜集、资料理解、数据组织；AI 配图不属于 MVP）
知识库搭建：在搜集记忆卡片的同时不断进化答疑助手
然后在后续的迭代中依照同上形式加入日程卡片、灵感卡片等场景的适配
这要求我们在搭建项目的初期就要考虑去做针对可扩展化的适配

次要：卡片社区：发布卡片集合、打卡、构建卡片仓库（一系列卡片集合）
