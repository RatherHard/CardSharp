# 删除 → 回收站：决策记录（2026-11-27）

> 需求来源：用户要求「删除之后是被移到回收站，保留状态，点恢复可以恢复到对应卡片集」。
> 依据：`docs/02-MVP需求文档.md` FR-2.5 / FR-2.2（回收站与恢复属于 P1，彻底删除与 30 天清理依赖后端）。
> 本文只记录**本轮拍板了什么、否掉了什么、为什么**，实现细节见 `docs/04-移动端开发须知.md` §20。

## 1. 范围

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 本轮做到哪一步 | 第一轮：删除进回收站 + 恢复（**不做**彻底删除、不做 30 天清理）。第二轮（2026-11-27，用户追加）：**补上永久删除**（多选：逐个勾选 / 全选 + 确认框），仍不做 30 天自动清理 | 永久删除在本地就能闭环，用户明确要「一个一个选和全选」；30 天清理要和服务端状态对齐，等后端 |
| 数据落哪 | 复用已有 `deleted_at`，卡片新增 `deleted_with_deck` | 卡片集删除要连坐其下卡片，单靠 `deleted_at` 无法区分「单独删的卡」和「跟着卡片集删的卡」 |
| schema 变更 | `schemaVersion` 1 → 2，`onUpgrade` 里 `addColumn` | 已有用户库要能平滑升级，不能清库 |
| 卡片集删除后封面 | **保留**本机封面副本 | 回收站里要能看见原封面；恢复后也应原样带回来。清理留到「永久删除」 |
| 永久删除的粒度 | 只删回收站里的东西：卡片集连带 `deleted_with_deck = 该集` 的卡片；单删卡片只删那张；正常卡片/卡片集一律不碰，且幂等 | 防止误把在用的数据物理删掉；不做「清空正常库」这种危险操作 |

## 2. 语义

| 场景 | 行为 |
| --- | --- |
| 删卡片集 | 集打 `deleted_at`；其下所有卡片打 `deleted_at = now`，`deleted_with_deck = deckId`；**更早被单独删过**的同集卡片合并进本批次（保留它们原来的删除时间） |
| 单独删卡片 | 只打该卡 `deleted_at`，`deleted_with_deck` 留空 → 回收站顶层按「卡片」列出并标注来源卡片集 |
| 恢复卡片集 | 集 + `deleted_with_deck = 该集` 的卡片一起清标记，按 `created_at` 回到原位 |
| 恢复单卡 | 必须选目的地：①原卡片集（若该集仍在回收站 → 连带恢复整集并提示）②新建卡片集（默认名 `<原集名>恢复`，可改） |
| 恢复顺序 | 回到原位（按 `created_at`），不追加到末尾 |

## 3. 界面

| 项 | 结论 |
| --- | --- |
| 入口 | 侧边栏「回收站」，带数量角标（卡片集数 + 单独删除的卡片数） |
| 分组 | 按天倒序；日期头 `11月27日`（跨年带年份）；同一天内先「卡片集」区，后「卡片」区 |
| 卡片集行 | 封面 + 名字 + 卡片数 + 「恢复」 |
| 卡片行 | 名字 + 「来自「X」」+ 「恢复」 |
| 回收站里的卡片集详情 | 点行进入只读列表：顶部「恢复整个卡片集」，每行「恢复」单卡（详情页内**没有**永久删除入口，永久删除只在回收站列表页做） |
| 永久删除入口 | 回收站页右上「选择」→ 多选态（行内勾选框、AppBar 显示「已选 N 项」+「全选」）→ 底部「永久删除」→ 确认框写「删除后无法恢复，确定永久删除选中的 N 项吗？」 |
| 删除按钮文案 | 保留按钮文字「删除」，提示改成「移到回收站……可以恢复」（不改成「移到回收站」当按钮名） |

## 5. 被否掉的方案

| 方案 | 否掉原因 |
| --- | --- |
| 回收站单独一张表（`trashed_decks` / `trashed_cards`） | 搬表要有搬回来的逻辑，且与「恢复回原位」的排序、封面、卡片关联都要重写；用 `deleted_at` 原地标记更省 |
| 卡片集删除时只删集、卡片留着 | 书架按集取卡片，留着会变成孤儿；且 FR-2.2 明确要求连带进回收站 |
| 回收站页用平铺列表（不按天分组） | 用户明确要求按天、且同天内集与卡分开；按天分组也便于将来加「30 天清理」的提示 |
| 单卡恢复默认放回原集、不给选择 | 原集可能已不在，或用户就是想挪到新集；给选择比猜默认值安全 |
| 删除时顺带清理本机封面 | 回收站期间没封面、恢复后也回不来 |
| 第一轮顺手做彻底删除 / 30 天清理 | 无后端支持；**第二轮用户明确要永久删除后已补上永久删除，但 30 天清理仍推迟**（定时任务与后端状态对齐成本高） |

## 6. 遗留

1. 30 天自动清理：等后端清理任务（永久删除已本地实现，见 §1 / §3）。
2. 卡片集计数在删除单卡后需要刷新书架：已用 `invalidate(decksControllerProvider)` 修掉，接后端后应改为读 `stats`。
3. 回收站里恢复「原卡片集」时，若原集在回收站，当前直接整集恢复并 `pop` 回收站详情页——交互上是否要先提示由用户确认，留待下次交互评审。
4. 永久删除目前只在回收站列表页做（多选/全选）；回收站里的卡片集详情页没有入口，是否要加「永久删除整个卡片集」待定。
