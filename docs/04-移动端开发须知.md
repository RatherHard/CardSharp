## 3. 代码约定（不要走样）

分层固定为四层，禁止跨层调用：

```
Widget → Notifier（Riverpod） → UseCase → Repository（Fake/Http 实现）
```

| 层 | 位置 | 规则 |
| --- | --- | --- |
| Presentation | `features/<f>/presentation/` | 只依赖 application 与 domain；**禁止直接 import data 层** |
| Application | `features/<f>/application/` | `Notifier` / `AsyncNotifier` + UseCase 的 `Provider` |
| Domain | `features/<f>/domain/` | 实体（freezed）、抽象接口、常量；无 Flutter 依赖 |
| Data | `features/<f>/data/` | 接口的 Fake / Http 实现 |

接后端时**只改两处**：新增 `HttpXxxRepository`，把 `xxxRepositoryProvider` 的实现换掉。页面、状态、路由都不用动。

其他约定：

- 主题：`mobile/lib/core/theme/app_theme.dart`（seed `0xFF4F46E5`，Material 3，跟随系统深浅色），不要在页面里硬编码颜色
- 文案：统一走 `mobile/lib/core/l10n/app_strings.dart`，不要在 Widget 里写中文字面量
- 路由：`mobile/lib/core/router/app_router.dart` 的 `routerProvider`，登录守卫在 `redirect` 里
- 3.50 起 Material 已拆包：统一 `import 'package:material_ui/material_ui.dart';`，**不要**再用 `package:flutter/material.dart`

### 9.2 新增依赖

```
file_selector ^1.1.0
```

- **来源**：Flutter 官方（flutter.dev 发布，属 flutter/packages 仓库）
- **用途**：导入卡片集时读取用户选中的 JSON 文件
- **权限**：走 Android Storage Access Framework，**不需要申请存储权限**
- **影响**：纯客户端依赖，不涉及后端接口与数据契约
- **引入原因**：Flutter SDK 不内置文件选择器；已与需求提出者确认后引入

### 9.3 导入文件格式

```jsonc
{
  "title": "卡片集名称",          // 必填，非空
  "description": "一句话简介",     // 可选
  "color": "#RRGGBB",             // 可选，格式不合法会被忽略
  "cards": [                       // 必填，至少一张
    {
      "plaintext": "问题/提示",     // 必填，≤200 字
      "ciphertext": "答案",         // 必填，≤500 字
      "hint": "提示",              // 可选
      "extra": "备注"              // 可选
    }
  ]
}
```

`fields` 内部的字段名与后端 `cards.fields`（`docs/03` §4.4）完全一致。但 `Card` 的外层字段
（`deckId` / `cardType` / `sortOrder`）在 Dart 里必须是小驼峰，后端 JSON 是下划线，**中间要靠
`@JsonSerializable(fieldRename: FieldRename.snake)` 自动转换**，见 §9.4 注意点 4。

校验失败会给出具体原因：不是 JSON / 顶层不是对象 / 缺 `title` / 没有 `cards` / 某张卡片缺明文暗文或超长。

### 9.4 接后端时要改的地方

**仓储注入点集中在组合根契约层**（`mobile/lib/core/di/repository_providers.dart`）：

```dart
// core/di/repository_providers.dart —— 只依赖 domain，默认实现一律抛错
final authRepositoryProvider = Provider<AuthRepository>((ref) => throw StateError(...));
final cardRepositoryProvider = Provider<CardRepository>((ref) => throw StateError(...));
final deckRepositoryProvider = Provider<DeckRepository>((ref) => throw StateError(...));
```

真正装配在 `mobile/lib/main.dart` 的 `ProviderScope(overrides: [...])` 里完成。换成 Http 实现时：

1. 新增 `HttpDeckRepository implements DeckRepository`（其余两个同理）；
2. 只在 `main.dart` 的 overrides 里把三个 `overrideWithValue(...)` 换成 Http 实例；
3. `application` 层（Notifier / UseCase）与页面**一行都不用改**——它们只认 domain 接口。

注意：`Provider` 故意不给默认实现（默认抛 `StateError`），这样「忘了注入」会在启动时立刻炸掉，而不是悄悄带着假仓储发版。

页面、Notifier、UseCase、路由都不用动，但下面这些契约细节必须跟着实现对上，否则「只换 provider」会在运行时出错：

**契约注意点**：

1. `Deck.cardCount` 已改为**不参与序列化**的纯展示字段（`@JsonKey(includeFromJson: false, includeToJson: false)`），导入用例也不再写入；接后端后由 `decks.stats` 填充
2. 导入目前是「建 deck → 改 deck → 批量加 cards」三步，**不是原子操作**；若后端能提供 `POST /decks:import`，应改为一次调用
3. 卡片 id 现在由假实现自增生成，接后端后一律由服务端分配
4. **序列化键名**：Dart 字段是小驼峰（`deckId`），后端 JSON 是下划线（`deck_id`），转换由模型上的
   `@JsonSerializable(fieldRename: FieldRename.snake)` 自动完成。已加注解的类：
   `Card` / `CardFields` / `CardImage` / `Deck`；`test/features/cards/domain/card_json_test.dart` 与
   `test/features/decks/domain/deck_json_test.dart` 锁住了这个契约。**新增带 `fromJson` 的模型必须同样加注解**，
   规则见 `AGENTS.md` §5.2。不要试图把 Dart 变量名改成下划线——`--fatal-infos` 会失败
5. **分页**：列表接口一律返回 `PagedResult<T>{items, nextCursor}`（`core/network/page.dart`），
   对应后端 `{items, next_cursor}` 与 `?cursor=&limit=`。`nextCursor` 是**不透明**游标，客户端原样回传、
   不解析。书架页滚到底自动取下一页；详情页为了「序号 / 全选 / 批量删除」需要完整列表，
   因此逐页拉完（最多 20 页 × 50 张）
6. **局部更新**：改卡片集走 `updateDeck(id, {title, description, color})`，只传改动字段，
   对应 `PATCH /decks/{id}`。**禁止**把整个 `Deck` 发回去——会把服务端的 `stats` / `config` /
   `updated_at` 覆盖成客户端默认值
7. **错误处理**：后端错误体是 `{error: {code, message, request_id}}`，由 `core/network/api_error.dart`
   的 `ApiError` 解析。页面已能识别三类：`isUnauthorized`（应跳登录）、`isNotFound`、`isValidation`。
   Http 实现应把非 2xx 响应转成 `ApiError` 抛出，页面会自动展示后端给的 `message`

| 现象 | 原因 | 处理 |

## 14. 卡片集导入文件格式（2026-11-26，已对齐后端列结构）

导入入口有两个，共用一份格式与一条调用链：
- 书架「+」→「导入 JSON 文件」（系统文件选择器，端口 `ImportFilePicker`）；
- 书架「+」→「导入示例卡片集」（内置 `assets/examples/deck-sample.json`，端口 `BundledDeckLoader`）。

解析写在 `features/decks/domain/deck_import.dart` 的 `parseDeckImport(String) → DeckImport`，纯函数、无 IO，
失败抛 `DeckImportException(DeckImportError)`；错误码到文案的翻译只在 `shelf_page.dart` 的 `_importErrorMessage` 里做。

### 14.1 文件骨架（字段名与 `docs/03` §4.2 的列一一对应）

```json
{
  "title": "奶蛙家族图鉴",
  "description": "按外形特征认出奶蛙家族的成员",
  "color": "#10B981",
  "card_type": "memory",
  "config": {},
  "cards": [
    {
      "sort_order": 1,
      "fields": {
        "plaintext": "奶蛙",
        "question": "奶蛙最明显的两个外观特征是什么？",
        "ciphertext": "绿眼睛、浅色肚皮",
        "images": [],
        "hint": "看眼睛",
        "extra": "来源：naiwahub"
      }
    }
  ]
}
```

### 14.2 字段表

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 卡片集标题，对应 `decks.title`（varchar 200） |
| `description` | 否 | 对应 `decks.description`，缺失按空串 |
| `color` | 否 | 只接受 `#RRGGBB` / `#AARRGGBB`，不合法按空串（走主题默认色） |
| `card_type` | 否 | 默认 `memory`；目前只支持记忆卡，其他值报 `unsupportedCardType` |
| `config` | 否 | 对应 `decks.config` jsonb，必须是对象；内容原样透传，不在这里解析 |
| `cards` | 是 | 至少一项；每项 `{card_type?, sort_order?, fields}` |
| `cards[].fields` | 是 | 对应 `cards.fields` jsonb，必须是对象 |
| `fields.plaintext` | 是 | 非空，≤200 字（`kPlaintextMaxLength`） |
| `fields.question` | 否 | 复习时显示的问句（≤200 字），**本地演示字段**：`docs/03` §4.4 的 `cards.fields` 没有这一列，见 §14.6 |
| `fields.ciphertext` | 是 | 非空，≤500 字（`kCiphertextMaxLength`） |
| `fields.images` | 否 | `[{key, width?, height?, alt?}]`，`key` 非空字符串（对象存储 key，不是 URL） |
| `fields.hint` / `fields.extra` | 否 | 提示与备注，缺失按空串 |
| `cards[].sort_order` | 否 | 整数；缺失时用数组下标参与排序（`(sortOrder ?? index)` 稳定排序） |

> 列表页只显示「序号 + `fields.plaintext`」，`ciphertext` 一律不展示（避免剧透答案）；示例资源里的 `plaintext`
> 因此用的是角色名（奶蛙 / 奶蛋 / …），完整问答内容放在 `ciphertext` 里。

### 14.3 导入时对应后端哪几个请求

`ImportDeckUseCase` 固定三步，与后端端点一一对应（**非原子**，中途失败会留下半成品，docs/04 §10.2 已记）：

1. `createDeck(title:, cardType:, config:)` → `POST /api/v1/decks`
2. `updateDeck(id, description:, color:)` → `PATCH /api/v1/decks/{id}`
3. `addCards(deckId, cardFieldsList)` → `POST /api/v1/decks/{id}/cards`（当前是一张一次；后端若加批量端点，只改这一步）

`id` / `deck_id` / `content_hash` / `stats` 由服务端生成，文件里**不写**。

### 14.4 待后端确认的三点（未写死，改起来都是局部）

1. `docs/03` §6.3 只给了 `/reviews` 与 SSE 的报文示例，**创建卡片集的请求体形状没写**（是否包一层 `{...}` 未知）→ 解析器只产出字段，包壳留给 `HttpDeckRepository`。
2. 没有批量建卡端点（`/cards/batch` 只做移动/打标签/删除）→ 导入 N 张会发 N 次请求；后端加批量端点后只改 `addCards` 的实现。
3. `fields.images` 有契约但没有上传接口 → 文件里可以写 key，但本期 App 不产生 key；卡片配图留到 E4。

### 14.5 小口径存疑（已记，不影响当前契约）

- 长度校验用 Dart `String.length`（UTF-16 码元），后端 Pydantic 按字符数；含 emoji 时前端更严。
- 解析器忽略未知字段：将来后端加字段，文件里写了也不会生效，需要同步改 `parseDeckImport`。

### 14.6 `fields.question` 是本地演示字段（接后端时要改的地方）

需求是「列表里显示卡片名、复习时显示问句」，一份 `plaintext` 装不下两种文案，所以本地临时加了 `fields.question`：

- 写入方：`parseDeckImport` 的 `_optionalQuestion`；
- 接后端时二选一：① 后端在 `cards.fields` 里加 `question` 列（推荐，改动最小，只删 `CardFields.question` 上的注释）；② 把问句放回 `plaintext`、另加 `name` 列显示卡片名。两种都要同步 `docs/03` §4.4、`card.dart`、`parseDeckImport`、`reviewQuestionOf` 四处。

### 14.7 卡片配图（本期是本地演示资源）

## 16. 复习页（运行，2026-11-26）

1. **问题面**：顶部进度条（`LinearProgressIndicator` + 「第 x / N 张」）→ 中心显示问句（`reviewQuestionOf(card)`：`fields.question` 非空先用，否则回退 `fields.plaintext`）→ 底部「查看」。

3. **卡片面**：点「查看本卡片」→ 页内翻出该卡完整正文（`CardDetailBody`：96×96 小图按 `BoxFit.contain` 整图缩进框内、不裁切 + 右侧暗文 + Tips + Agent 区 + 输入占位）→ 底部「收起」+「下一个」；「收起」回答案面。

「下一个」推进到下一张并把面复位到问题面；最后一张的按钮变「完成」→ 总结页「这一轮看完了 / 共看完 N 张卡片 / 再看一遍」。
