## 1. 目录与分层

```
mobile/lib/
├── core/
│   ├── di/          # 端口声明（只依赖 domain 接口）
│   ├── router/      # go_router 路由表与守卫
│   ├── theme/       # 主题、主题模式控制器
│   ├── network/     # ApiError、PagedResult 等传输层模型
│   └── l10n/        # AppStrings：全部用户可见文案
├── features/<feature>/
│   ├── domain/          # 实体（freezed）、仓储接口、失败枚举
│   ├── application/     # UseCase、Notifier/AsyncNotifier、状态类
│   ├── data/            # 仓储实现（Fake* / Http*）、本机存储实现
│   └── presentation/    # 页面与组件
└── shared/              # 跨 feature 复用的纯展示组件
```

### 1.1 依赖方向（铁律）

```
presentation → application → domain ← data
                                 ↑
                          core/di（端口）
```

| 层 | 允许依赖 | 禁止 |
| --- | --- | --- |
| `domain/` | Dart 标准库、freezed/json 注解 | import `data`/`application`/`presentation`；中文文案；IO |
| `application/` | `domain`、`core/di`(端口) | import `data/` 下的具体实现；`BuildContext` |
| `data/` | `domain` 接口、`core/`、第三方库 | 用户可见文案；依赖 `presentation` |
| `presentation/` | `application`、`domain` 实体、`core/l10n` | 直接调 Repository/HTTP；自己 new `data` 实现 |

**违反分层 = 直接打回。** 评审时按此表逐行检查 import。

## 2. 依赖注入

- 端口分两半，**不要混**：
  - 接口本体（`abstract interface class XxxService` / `XxxRepository`）定义在 `features/<feature>/domain/`，这样 `application` 只依赖 domain 就能拿到端口类型；
  - `Provider` 声明集中在 `core/di/`，按「数据来源 / 本机能力」分两个文件：
    - `lib/core/di/repository_providers.dart`：数据来源（auth / cards / decks …）
    - `lib/core/di/service_providers.dart`：本机能力（文件、选择器、资源加载、通知 …）
- 端口默认实现**必须抛错**，防止假实现悄悄进生产：
  ```dart
  final Provider<DeckRepository> deckRepositoryProvider = Provider<DeckRepository>(
    (Ref ref) => throw StateError('deckRepositoryProvider 未注入：请在组合根 main.dart 覆盖'),
  );
  ```
- **唯一装配点**是 `lib/main.dart`：
  ```dart
  ProviderScope(
    overrides: [
      deckRepositoryProvider.overrideWithValue(...),
      deckCoverServiceProvider.overrideWithValue(...),
    ],
    child: const CardSharpApp(),
  )
  ```
- 测试里同样只通过 `ProviderScope(overrides: [...])`（widget 测试）或 `ProviderContainer.test(overrides: [...])`（纯 Dart 测试）注入内存实现（`test/support/` 下放共用假实现）。
- 组合根之外（`lib/` 内任何其它文件）**禁止**出现 `overrideWithValue`；测试文件不受此限，但也要走上面的 overrides 入口。

## 3. 命名

| 对象 | 规则 | 例 |
| --- | --- | --- |
| 文件 | `snake_case.dart` | `deck_cover_service.dart` |
| 类/枚举 | `PascalCase` | `DeckCoverService`、`DeckFailure` |
| 私有成员 | `_camelCase` | `_storage`、`_pickCoverImage` |
| 常量 | `k` 前缀 + 小驼峰 | `kSeedDecks`、`kPlaintextMaxLength` |
| 端口 | `<名字>Provider` | `deckRepositoryProvider` |
| Widget Key | `snake_case`，`'<区域>_<组件>[_<动作>]'` | `shelf_create_button`、`deck_cover_pick_image` |
| 路由 path | kebab-case | `/deck/:id`、`/settings`、`/assistant` |

- Widget Key 是测试与自动化点按的契约，**不要随手改名**；新增交互必须给 Key。
- 不出现拼音缩写、不出现 `helper`/`util` 这类无信息词（除非确实是纯函数集合，命名为 `<领域>_utils` 并只放纯函数）。

## 4. 错误处理

四层各司其职，**文案只出现在展示层**：

| 层 | 职责 |
| --- | --- |
| `domain` | 定义 `enum XxxFailure { ... }` + `class XxxException implements Exception { const XxxException(this.failure); final XxxFailure failure; }` |
| `data` | 失败时抛上述异常（Fake 与 Http 实现口径一致）；HTTP 错误转换为 `ApiError(code, message?, requestId?)` |
| `application` | 把失败转成可展示的状态（如 `signIn` 返回 `AuthFailure?`），**不返回中文** |
| `presentation` | 唯一翻译处：`switch (failure)` → `AppStrings`，兜底 `AppStrings.unknownError` |

规则：

1. 用户可见的失败**必须给反馈**（SnackBar / 内联错误 / 错误态页面），禁止静默 `return`。
2. 破坏性操作（删除、覆盖）必须二次确认，文案写明后果。
3. 不要用 `throw` 表达「可预期且要展示给用户」的业务分支时泄漏内部细节（ID、SQL、堆栈）。
4. 捕获异常只在**能处理**的地方；不要 `catch (e) {}`。

## 5. 文案

- 全部用户可见字符串集中在 `lib/core/l10n/app_strings.dart`：
  ```dart
  abstract final class AppStrings {
    static const String shelfCreateTooltip = '新建卡片集';
    static String deckCardCount(int count) => '$count 张卡片';
  }
  ```
- 禁止在 `data/`、`application/`、`domain/` 写中文字面量；禁止在 widget 里硬编码中文。
  - **假数据例外**：`Fake*Repository` 里的种子数据标题（如 `kSeedDecks` 的「卡片集1..6」）属于数据、不属于界面文案，接后端后整体删除，允许留在 `data/`；
  - 内置示例卡片集的标题是唯一需要跨层对齐的字符串（展示层按它配演示封面），收口成 `AppStrings.sampleDeckTitle`，并由 `test/features/decks/data/asset_bundled_deck_loader_test.dart` 对齐 `assets/examples/deck-sample.json`。
- 带参数的文案写成静态方法，不要字符串拼接散落各处。
- 文案需要本地化时再上 `flutter_localizations` + ARB；当前集中常量已足够，**不要提前引入**。

## 6. 状态与异步（Riverpod 3）

- 状态类：`freezed` 定义（`auth_state.dart`、`deck.dart` 为范例）。
- 控制器：`AsyncNotifier` / `Notifier`；只通过 UseCase 访问数据。
- **Riverpod 3 的 API 坑（实测）**：
  - 读值用 `.value`，**没有** `valueOrNull`；
  - `Override` 未导出：写 `overrides: [ ... ]`，不要写 `<Override>[...]`；
  - `FutureProvider.family` 的显式类型（`FutureProviderFamily`）未导出：交给类型推断；
  - `Provider` 回调参数类型写 `(Ref ref)`。
- family provider 的参数用 **ID（String）**，不要传实体对象（对象作为 key 会导致失效判断混乱）。
- 数据变更后：`ref.invalidate(provider(arg))` 或 `state = await AsyncValue.guard(...)`；不要手动改 `AsyncData.value`。
- `setState` 回调里不要写箭头函数返回 Future（会触发 `setState() callback argument returned a Future`），用块语句。

## 7. 序列化与后端契约

- 新增任何带 `fromJson`/`toJson` 的模型**必须**：
  ```dart
  @freezed
  @JsonSerializable(fieldRename: FieldRename.snake)
  abstract class Deck with _$Deck { ... }
  ```
  后端字段是 `deck_id`，Dart 侧保持小驼峰，靠注解映射；**不要**把 Dart 变量名改成下划线（`--fatal-infos` 会因 `non_constant_identifier_names` 失败）。
- 客户端派生字段（如 `cardCount` 由后端统计）加：
  ```dart
  @JsonKey(includeFromJson: false, includeToJson: false)
  ```
- 列表分页统一 `PagedResult<T>{ items, nextCursor }`，游标对客户端不透明，只回传不解析。
- 接口形状变更属于「必须问人类」的范围（见 `AGENTS.md` §9.2）。

## 8. 测试

### 8.1 分层要求

| 改动 | 最低要求 |
| --- | --- |
| `domain/`（含解析、校验、纯函数） | 单测覆盖 ≥90%，含有效/无效/边界 |
| `application/`（UseCase、控制器） | 正例 + 反例（异常路径） |
| `data/`（Fake/文件实现） | 每个公开方法至少 1 例，含自愈/清理路径 |
| `presentation/` 关键交互 | Widget 测试：入口可见、点击后状态正确、错误可见 |
| 纯文档 | 免测 |

### 8.2 写法约定

- 测试目录镜像 `lib/`：`test/features/<feature>/{domain,data,application,presentation}/...`；共用假实现放 `test/support/`。
- Widget 测试默认视口 800×600 **太小**，会找不到第 7 个瓦片：
  ```dart
  tester.view.physicalSize = const Size(1080, 2400);
  tester.view.devicePixelRatio = 1;
  addTearDown(tester.view.reset);
  ```
- `testWidgets` 用的是假时钟：**真实文件/资源 IO 会卡住**（`await rootBundle.loadString` 永不返回）。
  - 要么 `await tester.runAsync(() => loader.load())`；
  - 要么把 IO 抽成可注入的 loader，测试注入内存实现；资源真实性的校验放到普通 `test` 里。
- 平台通道（`flutter_secure_storage`、`SharedPreferences`、`path_provider`）在测试里必须注入内存实现，或 `SharedPreferences.setMockInitialValues({})` + `TestWidgetsFlutterBinding.ensureInitialized()`。
- 断言要具体：`find.byKey(...)`、`find.text(...)`、宽高数值；不要只断言「不抛异常」。
- 禁止 skip/xfail 留在主干；禁止为过测试放宽断言。

## 9. 质量门禁（提交前必跑）

```powershell
cd mobile
dart format --line-length 100 lib test
flutter analyze --fatal-infos
flutter test
flutter build apk --debug      # 涉及界面/插件时必跑
```

- `--fatal-infos`：`info` 级也算失败，零告警是**硬门槛**。
- 改了注解模型后：`dart run build_runner build`，并把生成代码一起提交（`--delete-conflicting-outputs` 在当前 build_runner 版本已废弃，加了只会告警）。
- CI（`.github/workflows/ci.yml` mobile job）顺序：`pub get` → `build_runner` → `dart format --line-length 100 lib` → 校验 `git status --porcelain lib`（生成代码必须已提交）→ `dart format --set-exit-if-changed` → `flutter analyze --fatal-infos` → `flutter test --coverage`（覆盖率门槛 60%）。
  - 为什么生成后要先 format 一次：生成器按 80 列输出，仓库提交的是 `--line-length 100` 格式化后的版本；不先 format，「生成代码必须已提交」和「格式必须符合」会互相打架（`card.g.dart` 必红）。format 只改空白格式，真正的未提交改动照样会被 `git status` 拦下。
- 构建报 `PathExistsException ... 已存在时，无法创建该文件` → 先 `flutter clean` 再构建。
- 提交钩子：仓库自带 `.githooks/pre-commit`，拦截**单个文件 > 20 KB**（生成代码 `*.g.dart` / `*.freezed.dart`、`pubspec.lock`、`assets/`、`build/` 除外）。每个 clone 各启用一次：`git config core.hooksPath .githooks`；被拦时按报错把文件拆开，不要用 `--no-verify` 绕过（见 §11）。

## 10. 界面改动的交差标准

用户看到的是装进设备的 App，**测试通过不算验证**。交差必须四件套：

1. **做了什么**（一两句）
2. **测试命令与通过数**（`flutter test` 的通过例数）
3. **截图路径**（每点一步截一张）
4. **没验证到的**（如实列出）

操作流程（`mobile/` 下）：

```powershell
flutter build apk --debug
adb install -r build\app\outputs\flutter-apk\app-debug.apk
adb shell am force-stop com.cardsharp.cardsharp
adb shell am start -n com.cardsharp.cardsharp/.MainActivity
adb shell screencap -p /sdcard/s.png     # 不要用 exec-out ... > s.png
adb pull /sdcard/s.png shot.png
adb shell input tap <x> <y>              # 每点一步截一张
```

坑：

- 每次交差前**重新** build + `install -r`，不要复用上一轮的包。
- 点按坐标必须从**真图**换算：`read_image` 预览会把图缩小（1080×1920 → 961×1708，系数 ≈1.124）；按预览坐标点会偏。
- LDPlayer 默认横向 1920×1080，竖屏布局会被挤坏；先 `ldconsole modify --index 0 --resolution 1080,1920,420`。
- 主题/登录态是持久化的：验证完切回「跟随系统」或「浅色」，别把设备留在深色。

- 提交：Conventional Commits，**中文正文**，subject ≤50 字、不加句号，一次只做一件事。
  ```
  feat(mobile): 登录态持久化与设置页，仓储装配下沉到组合根
  ```

## 13. 常见坑速查（都是踩过的）

| # | 症状 | 原因 / 解法 |
| --- | --- | --- |
| 1 | `The name 'Override' isn't a type` | Riverpod 3 未导出 `Override`；去掉 `<Override>` 泛型 |
| 2 | `valueOrNull` 未定义 | Riverpod 3 用 `.value` |
| 3 | `package:flutter/material.dart` 触发 info 报错 | 换 `package:material_ui/material_ui.dart` |
| 4 | widget 测试找不到第 7 个元素 | 默认视口 800×600，改 `tester.view.physicalSize` |
| 5 | `testWidgets` 里加载资源/文件永久挂起 | 假时钟 + 真 IO；用 `tester.runAsync` 或注入 loader |
| 6 | 测试里 secure storage 抛平台通道缺失 | 注入 `InMemoryAuthStorage` 等内存实现 |
| 7 | `setState() callback argument returned a Future` | 箭头函数改块语句 |
| 8 | 构建 `PathExistsException` | `flutter clean` 后重建 |
| 9 | Android 构建卡在 Gradle 下载 | 预置发行包 / 走镜像；别等 |
| 10 | `data/` 目录文件没进仓库 | `.gitignore` 规则缺前导斜杠，改 `/data/` |
| 11 | 自动化点按没反应 | 预览坐标≠真机坐标（≈1.124）；先在真图算 |
| 12 | 主题莫名变深色 | 设置页的持久化值；切回浅色/跟随系统再交差 |
| 13 | 自己的未提交改动整片消失 | 对**有未提交改动**的文件跑过 `git checkout -- <file>`（恢复到 HEAD）。临时改动只 `git reset` 取消暂存后手动删；要留退路先 `git stash push -- <file>` |
| 14 | 钩子把 24 KB 的新文件拦下来 | 这是 `.githooks/pre-commit` 的正常行为；按报错拆文件，别加 `--no-verify` |
